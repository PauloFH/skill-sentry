Security plugin for Claude Code and Codex

Your plugins run with your privileges. Watch them with <skill-sentry/>

It audits the plugins, skills, hooks and MCP servers you install in Claude Code and OpenAI Codex, guards risky tool calls as they happen, hardens your Claude Code settings and recommends hardening for Codex.

Local and readable, with zero dependencies. No network calls, no telemetry.

Why it matters

Extensions are code. Some of it is hostile.

A plugin or skill is not just text Claude reads. It is software that runs on your machine, as you, right next to your SSH keys, cloud credentials and API tokens. When researchers examined the public skills ecosystem, this is what they found:

26.1%

of 31,132 public skills had at least one vulnerability.

5.2%

showed high-severity patterns that strongly suggest malicious intent.

2.12×

more likely to be vulnerable when a skill bundles executable scripts.

Source: the “Agent Skills in the Wild” study, January 2026.

August 2026

An npm worm came with a Claude Code hook.

The keyv npm worm shipped a .claude/settings.json with a SessionStart hook: a command that runs whenever a Claude Code session starts in that project. Your agent's configuration is part of the attack surface now.

What an extension can run on your machine

  • Hooks

    Shell commands when a session starts and before or after every tool call.

  • MCP servers

    Long-running processes launched under your user account.

  • Monitors

    Background processes a plugin keeps running while you work.

  • bin/ on your PATH

    Executables a plugin adds to the PATH of Claude's shell.

  • !`cmd` lines

    Inline shell in a skill, executed as soon as the skill is invoked.

  • Self-granted allowed-tools

    Frontmatter that lets a skill use tools without asking you first.

skill-sentry inventories and scans every one of these.

What it does

Three layers. One plugin.

Audit what is already installed, guard what happens next, and close the doors you don't need open.

Audit

/skill-sentry:audit

A static scanner reads every installed plugin, skill, hook and MCP server config, scores each component and explains what it found.

  • 12 finding categories, from credential theft and exfiltration to persistence and prompt injection
  • Vet a folder before you install it, with --path
  • A baseline shows what changed since your last audit
  • Claude can add its own opinion, but never lowers the scanner's verdict

Guard

PreToolUse hook

Inspects tool calls as they happen and blocks, or asks you, before the dangerous ones run.

  • Watches Bash, PowerShell, file tools, WebFetch and MCP calls
  • Knows when a skill or plugin is the likely origin of a call
  • Asks before anything writes to its own files
  • Fails open: if the guard errors, the call proceeds and the error is logged

Harden

/skill-sentry:harden

Reviews your settings.json and applies only the tightening steps you approve, one at a time.

  • Deny reading ~/.ssh and ~/.aws
  • Ask before curl, wget and .env reads
  • Optionally turn off inline shell in skills
  • Timestamped backup before any change

How it works

Every risky call gets a decision.

The guard checks each tool call against the scanner's rules, typically in about 50 ms, and answers with one of three decisions.

DecisionWhen
denyblocked A critical rule matches: download-and-execute pipes, reverse shells, crypto-miner launches, disk or home-directory wipes. Always blocked unless you allowlisted that exact command.
askyou confirm A high-risk rule matches and a skill or plugin is the likely origin. Also always for writes to skill-sentry's own files, and for unusual Windows path forms such as device paths, UNC paths, 8.3 short names and NTFS streams.
logrecorded A high-risk rule matches, but no skill or plugin is attributed as its origin. Written to guard.log, without interrupting you.

Everything else passes untouched. Data stays in ~/.claude/skill-sentry/.

Also in Codex

Same checks, now in OpenAI Codex.

The audit reads your Codex setup, Windows and WSL included: config.toml, execution rules, plugins, hooks and their trust state, MCP servers, skills and AGENTS.md. The guard runs as a PreToolUse hook with five tiers. Codex has no “ask”, so every decision is allow or deny.

TierWhat the guard does in Codex
denytier 1 A critical rule matches. Denied.
denytier 2 A high rce, exfil, miner or destructive rule; a secret and network egress in one command; or a network-capable call after a skill or plugin call that read a secret was allowed on retry earlier in the session. Denied: if you meant it, run it yourself in a terminal.
retrytier 3 Any other high rule with a skill or plugin behind it. Denied the first time, with the reason. An identical retry in the same session within 10 minutes is allowed once.
logtier 4 A high rule with no skill or plugin attributed. Logged only.
denytier 5 Writes to skill-sentry's own files (any installed copy), or through unusual path forms. Denied.

Patches sent through apply_patch are inspected too. Most patches the guard cannot read, from a file, a pipe or shell expansion, are denied. Dynamic or obfuscated shell is not analysed.

Main limits under Codex

  • No “ask”: the guard can only allow or deny.
  • It fails open: if the hook errors or runs past Codex's timeout, about 5 seconds, the call runs.
  • Until you trust the hook in /hooks, the guard does not run.
  • After a plugin update Codex marks the hook modified and stops running it until you trust it again in /hooks.
  • Commands that build names or paths at run time (eval, variables, globs, python -c) are not analysed.
  • Harden is recommend-only: skill-sentry never edits Codex files. harden.mjs check --agent codex prints snippets for you to apply.
  • Update both installs after each release, so the Claude Code and Codex copies match.

The README lists every limit, with the WSL notes.

Honest limits

A second pair of eyes, not a shield.

A security tool that overpromises is a risk of its own. Read this before you trust skill-sentry.

  1. Not an antivirus, not a sandbox. It doesn't isolate anything and can't undo damage.
  2. Static analysis only. The scanner reads files with pattern rules and never runs them. Sufficiently creative code can evade pattern rules.
  3. Blind to other plugins' hooks while they run. It reads their configuration and scripts, not their live behavior.
  4. Can't inspect code fetched at runtime, like a package launched with a floating version tag or a script downloaded and then run. It can only flag that this happens.
  5. The guard is best-effort. Sufficiently obfuscated shell can bypass it. For Write and Edit it checks the target path, never the content.
  6. A clean report is not proof of safety. A bad report is a reason to look closer.

Worth doing regardless

  • Pin plugin versions
  • Avoid auto-update for third-party marketplaces
  • Read what you install
  • Apply the settings from /skill-sentry:harden
